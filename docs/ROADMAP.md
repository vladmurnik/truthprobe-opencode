# Дорожная карта TruthProbe 0.5

Документ составлен по состоянию на 19.11.2026, после запуска собранного бинаря и разбора
кейса «`opencode/deepseek-v4.1-flash-free` — цифр нет». Пять задач ниже закрывают ровно
то, что мешает отдать проект людям: непонятно, какие модели работают; установка требует

скоринг нельзя заменить своим.

Порядок исполнения: **T3 → T4 → T1 → T2 → T5**. T3 и T4 трогают одни и те же файлы UI,
поэтому делаются подряд. T1 и T2 не зависят от кода. T5 — самый большой и делается
последним, когда шкала уже зафиксирована.

## T3. Шкала уверенности и уровни (первым)

**Проблема.** `answer confidence 71%` не говорит человеку ничего: 71% — это много или
мало? Сейчас порог один (`riskyThreshold = 0.45` в `packages/core/src/truthprobe/types.ts:77`),
и он нигде не объяснён. Уровни `shakyThreshold = 0.3` уже объявлены в типах, но не
используются.

**Что делаем.**

1. Новый модуль `packages/core/src/truthprobe/levels.ts`:

   ```ts
   export type ConfidenceLevel = "safe" | "likely" | "uncertain" | "risky" | "unreliable"
   export function levelOf(score: number | null): ConfidenceLevel | null
   ```

   Границы (единый источник правды, экспортируются как `LEVEL_BOUNDS`):

   | уровень | score | смысл |
   | --- | --- | --- |
   | `safe` | ≥ 0.90 | модель шла почти без колебаний |
   | `likely` | 0.75 – 0.90 | уверенно |
   | `uncertain` | 0.55 – 0.75 | заметные колебания |
   | `risky` | 0.35 – 0.55 | много развилок, ответ шаткий |
   | `unreliable` | < 0.35 | модель фактически угадывала |

2. Поле `level` добавляется в `AnswerScore` и `SentenceScore`
   (`packages/core/src/truthprobe/types.ts`), заполняется в `scoreAnswer`
   (`score.ts`). Все потребители (`session-ui`, `tui`, будущий REST) читают уровень
   из парта, а не считают его сами.

3. Отображение:
   - ответ: `answer confidence 71% · uncertain`
   - предложение: `! #2 46% · risky: Чем займёмся?`
   - `unavailable`: `no confidence signal · provider sent no logprobs`
   - мета-строка бейджа: только уровень (`uncertain`), без процента — процент уходит в тело.

4. Обязательный дисклеймер в README (одним абзацем, рядом с таблицей уровней):
   проценты — это уверенность модели в собственных токенах, а не вероятность
   правдивости. Детерминированный шлюз (logprob ≈ −0.001) даёт `safe` на любом тексте.

5. Конфиг: `truthprobe.thresholds: { risky?: number, shaky?: number }` в
   `opencode.jsonc`, маппится в `ScoreOptions`. Дефолты не меняются.

**Приёмка.**
- `bun test packages/core/test/truthprobe.test.ts` — новый кейс на `levelOf` (границы, `null`).
- В живом прогоне на `freepi/deepseek-v4.1-flash` строка содержит и процент, и уровень.
- `rg "answer confidence" packages` показывает, что ни один UI не форматирует процент без уровня.

## T4. Подсветка сомнительных предложений

**Проблема.** В кейсе пользователя строка `! #2 46%: Чем займёмся?` присутствует, но
цветом не выделена. Факты: посентенсный флаг ставится по `risk >= riskyThreshold`
(`score.ts:234`), то есть 46% попадает в флаг корректно; в `message-content.tsx`
используется только цвет текста `text-[var(--v2-yellow-900)]` (#ac8833) — на тёмной теме
это почти неотличимо от основного текста. Фона нет.

**Что делаем.**

1. Заменить «цвет текста» на «плашку»: левая граница + слабый фон, интенсивность по уровню.

   | уровень | класс |
   | --- | --- |
   | `risky` | `border-l-2 border-[var(--v2-state-border-warning)] bg-[color-mix(in_oklab,var(--v2-yellow-900)_10%,transparent)]` |
   | `unreliable` | `border-l-2 border-[var(--v2-state-border-danger)] bg-[color-mix(in_oklab,var(--v2-red-900)_10%,transparent)]` |

   Применяется и к строке меты, и к списку предложений, в `session-ui` и в `tui`
   (в TUI — только префикс `▌` + цвет, без фона).

2. Токены для красного проверить перед использованием: `--v2-red-900` /
   `--v2-state-border-danger` должны существовать в `packages/ui/src/styles/tokens/colors.css`;
   если нет — добавить по образцу `--v2-yellow-900` и зарегистрировать в `default-primitives.ts`.

3. Порог «сомнительности» привязать к уровню, а не к отдельному числу: помечаем
   `risky` и `unreliable`. `riskyThreshold` остаётся для обратной совместимости и
   вычисляется как граница `likely/uncertain` при кастомных `thresholds`.

**Приёмка.**
- Скриншот тёмной темы: 46%-предложение видно с первого взгляда (фон + граница).
- `bun test` зелёный; тест на `doubtfulSentences` возвращает предложения обоих уровней.
- В TUI строка не ломает выравнивание (проверить `--print-logs` в 80 и 120 колонок).

## T1. Матрица поддержки моделей в README

**Проблема.** Люди ставят патч и ждут цифр на `opencode/deepseek-v4.1-flash-free`, а
этот провайдер logprobs не отдаёт вообще (проверено: `reason: "no logprobs in response"`
при принудительном `OPENCODE_TRUTHPROBE=1`). Ожидание и реальность расходятся, и это
выглядит как поломка.

**Что делаем.**

1. `scripts/probe-models.ts` — CLI: принимает список `provider/model`, делает один
   стриминговый запрос с `logprobs: true, top_logprobs: 20` через штатный провайдер,
   печатает JSON `{model, ok, tokens, reason}` и умеет `--md` — собирать таблицу.
   Результат кладётся в `docs/MODEL-SUPPORT.md` (генерируемый файл, дата в шапке).

2. Таблица из трёх состояний, с явной формулировкой последствий:

   | состояние | что видит человек |
   | --- | --- |
   | ✅ logprobs есть | проценты и уровни под каждым ответом |
   | ⚠️ только через свой endpoint | нужен OpenAI-совместимый шлюз с `logprobs` |
   | ❌ logprobs нет | строка `no confidence signal` + причина, цифр не будет никогда |

3. Известные на сегодня факты (внести в таблицу как проверенные):
   - `freepi/particle`, `freepi/deepseek-v4.1-flash` — ✅ (0.798 / 0.689);
   - `opencode/deepseek-v4.1-flash-free` — ❌ (проверено);
   - OpenAI-совместимые шлюзы (llama.cpp, vLLM, LM Studio) — ✅ при включённом `logprobs`;
   - Anthropic Claude, Google Gemini — ❌ по API (зафиксировать после проверки, не по памяти).

4. Раздел README «Какие модели работают» сразу после установки, со ссылкой на
   `docs/MODEL-SUPPORT.md` и на пункт «первый запрос при пустом кэше идёт без цифр».

**Приёмка.**
- `bun run scripts/probe-models.ts --md freepi/particle opencode/deepseek-v4.1-flash-free`
  выдаёт таблицу без ручной правки.
- README (ru + en) содержат таблицу и фразу «цифр не будет, если провайдер не отдаёт logprobs».
- В `docs/VALIDATION.md` §9 добавлена строка с датой прогона.

## T2. Установка одним скриптом

**Проблема.** Сейчас `install.sh` / `install.ps1` клонируют `sst/opencode` и собирают
с нуля. Это отпугивает: нужен git, bun, 8 минут сборки, и всё равно получится отдельный
бинарь, а не «мой opencode с патчем».

**Что делаем.** Один самодостаточный файл на платформу, запускаемый без клонирования
репозитория:

```powershell
irm https://raw.githubusercontent.com/vladmurnik/truthprobe-opencode/master/install.ps1 | iex
```

```sh
curl -fsSL https://raw.githubusercontent.com/vladmurnik/truthprobe-opencode/master/install.sh | sh
```

Флаги (одинаковые в обоих):

| флаг | смысл |
| --- | --- |
| `--dir <path>` | куда ставить (по умолчанию `~/opencode-truthprobe`) |
| `--target <rev>` | база `sst/opencode` (по умолчанию пин `007afb1`) |
| `--patch-existing` | применить патч в **существующий** чекаут пользователя |
| `--scorer <path>` | подключить свой скорер (см. T5) |
| `--dry-run` | только проверить окружение и применимость патча |
| `--uninstall` | `git am --abort` / удалить каталог |

Требования к поведению:

1. Преflight: версия git, bun, свободное место; внятное сообщение, если bun нет, со ссылкой.
2. `--patch-existing` отказывается работать на грязном дереве без `--force`, создаёт
   ветку `truthprobe`, при конфликте делает `git am --abort` и возвращает дерево как было.
3. После установки — самопроверка: `opencode --version` и один прогон с
   `OPENCODE_TRUTHPROBE=1`, проверка, что в парте появился `truthprobe.status`.
   Провал самопроверки = ненулевой код возврата и инструкция, куда смотреть.
4. Ничего не пишет в `~/.config/opencode` без `--config`; провайдерские настройки не трогает.
5. `--uninstall` удаляет ветку и каталог, оставляет пользовательский конфиг.

**Приёмка.**
- Чистая Windows-машина с git + bun: одна команда → цифры в TUI.
- `--dry-run` на машине без bun печатает понятную ошибку и код ≠ 0.
- `--patch-existing` на чекауте с локальными правками либо аккуратно применяется,
  либо откатывается без потерь (проверить на копии).

## T5. Сменный ML-скоринг

**Проблема.** Сейчас оценка жёстко зашита: геометрическое среднее по logprob с весами
(`globalWeight = 0.6`). Пользователь хочет подставлять свою модель, которая по
распределению вероятностей токенов выдаёт уверенность.

**Что делаем.**

1. Контракт в `packages/core/src/truthprobe/scorer.ts`:

   ```ts
   export interface ScoreInput { text: string; tokens: TokenLogprob[]; options: ScoreOptions }
   export type Scorer = { id: string; score(input: ScoreInput): AnswerScore | Promise<AnswerScore> }
   ```

   `scoreAnswer` становится обёрткой над выбранным скорером. Встроенные:
   `geometric` (текущее поведение, дефолт), `min-token`, `entropy`.

2. Выбор скорера в конфиге:

   ```jsonc
   { "truthprobe": { "scorer": "geometric" } }
   { "truthprobe": { "scorer": "module:./my-scorer.mjs" } }
   { "truthprobe": { "scorer": "http://127.0.0.1:8080/score" } }
   ```

   `module:` — ESM-файл с `export default (input) => AnswerScore`;
   `http:` — POST `{text, tokens}` → `AnswerScore`. Таймаут 300 мс, при ошибке или
   невалидном ответе — откат на `geometric` и одна запись в лог (не спамить).

3. Калибровка как путь к «своей модели»: `scripts/calibrate.py` уже считает AUROC/ECE.
   Добавить `--fit` — логистическая регрессия на CSV `sentence,label`, выход
   `truthprobe-weights.json` (веса признаков: средний logprob, минимальный logprob,
   энтропия топ-20, отрыв топ-1 от топ-2, длина предложения). Загрузчик
   `scorer: "linear:./truthprobe-weights.json"` — интерпретируемый вариант без внешних
   зависимостей и без произвольного кода.

4. Документ `docs/CUSTOM-SCORER.md`: формат входа/выхода, пример на 20 строк,
   как проверить свой скорер на сохранённых партах, предупреждение о безопасности
   (`module:` исполняет произвольный код — только для своих файлов).

**Приёмка.**
- `scorer: "geometric"` даёт бит-в-бит те же числа, что сейчас (регрессионный тест на фикстуре).
- `module:`-скорер из `docs/CUSTOM-SCORER.md` возвращает предсказуемые значения в тесте.
- При падении скорера ответ помечается `partial` с причиной `scorer failed: <msg>`, а не молчит.
- `--fit` на демо-наборе печатает AUROC и сохраняет валидный JSON.

## Риски

1. **Уровни создают ложную точность.** Митигация: подпись «уверенность в токенах, не в правде»
   рядом с каждым уровнем и в README; никаких «% правдивости».
2. **Уровни зависят от провайдера.** Детерминированные шлюзы всегда `safe`. Митигация:
   в README отдельный абзац про шлюзы; в будущем — нормировка на энтропию (`entropy`-скорер).
3. **`module:`-скорер = исполнение чужого кода.** Митигация: только локальные пути,
   `http:` как песочница, откат на `geometric` при любой ошибке, предупреждение в доках.
4. **`--patch-existing` может испортить чужой репозиторий.** Митигация: отдельная ветка,
   отказ на грязном дереве, `git am --abort`, `--dry-run`.
5. **Расхождение ru/en README.** Митигация: таблицы уровней и моделей генерируются
   скриптами (`--md`), руками правится только текст вокруг.
