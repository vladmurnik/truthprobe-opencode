# Калибровка

**Статус: не выполнена.** Ни AUROC, ни ECE, ни precision/recall на размеченном наборе не измерены.
Всё, что есть сейчас, — два живых ответа из `VALIDATION.md` §9 без меток «правда/ложь».

Пока калибровки нет, проценты в UI читаются так: **насколько ровно модель шла по этому тексту**.
Это не вероятность правды и не вероятность галлюцинации. Порог `riskyThreshold = 0.45` и веса
`0.4 geo + 0.3 worst + 0.3 phi` подобраны на одном мок-примере, а не на данных.

## Что нужно, чтобы это стало измерением

1. **Набор.** 200–500 предложений из реальных ответов, каждое с меткой `true` / `false` /
   `unverifiable`. Метки ставит человек по источникам; `unverifiable` не выбрасывать, а считать
   отдельно — иначе метрика смещается в сторону проверяемых фактов.
2. **Признаки по предложению.** Считать и хранить отдельно: `geo`, `minLp`, `phi`, `meanLp`
   (уже есть в `SentenceScore`), плюс `logprob первого токена` и длину предложения.
3. **Метрика на признак, а не на смесь.** AUROC каждого сигнала против метки. Только после этого
   веса — логистической регрессией на кросс-валидации, а не «на глаз».
4. **Порог из политики.** Precision/recall при разных порогах: сколько ложных флагов на 100 верных
   предложений мы готовы показывать.
5. **ECE.** Сравнить заявленную уверенность с наблюдаемой частотой «правда» по бинам.

## Инструмент

`scripts/calibrate.py` считает AUROC и ECE по JSONL с полями `score`, `phi`, `meanLp`, `minLp`,
`label` и печатает таблицу. Пока в репозитории нет размеченного файла, скрипт запускается только с
`--demo`, который генерирует синтетику — это проверка кода, а не измерение модели.

## Пока калибровки нет: правила честности в UI

- `unavailable` показывается с причиной, а не скрывается.
- `first-token confidence` назван первым токеном, а не «первым предложением».
- `answer confidence` виден всегда, включая хорошие ответы.
- README и этот файл прямо говорят, что проценты не откалиброваны.


## Обучение весов скорера

```bash
python3 scripts/calibrate.py labeled.jsonl --fit --out truthprobe-weights.json
```

Печатает AUROC и ECE по out-of-fold предсказаниям (5 фолдов), затем веса линейной модели:
`score = sigmoid(bias + w1·meanLp + w2·minLp + w3·meanPhi + w4·fracLow)`.
Веса кладутся в JSON и включаются переменной `TRUTHPROBE_SCORER=linear:<путь>`.
Классы сбалансированы при обучении, L2 = 1e-3.

Важно: пока веса обучены на синтетике (`--demo`), доверять цифрам нельзя — нужен набор
из 200–500 реальных предложений с метками «правда / ложь», размеченных по источникам.
